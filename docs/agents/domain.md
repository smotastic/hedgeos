# Domain documentation

HedgeOS is a single-context repository. Before exploring a product area, read
`CONTEXT.md` and the relevant ADRs under `docs/architecture/adr/`. Read
`docs/project-principles.md` when making implementation or workflow decisions.

Use the vocabulary defined in `CONTEXT.md` in issue titles, specifications,
tests, and implementation discussions. If a term is ambiguous or conflicts
with the glossary, resolve the language before introducing a new synonym.

When a decision is hard to reverse, surprising without context, and the result
of a real trade-off, record it as an ADR. Do not use ADRs for ordinary
implementation details or temporary Wayfinder discussion. If a new decision
conflicts with an existing ADR, call out the conflict explicitly and decide
whether the ADR should be superseded.
